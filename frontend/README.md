# Менеджер расписания школы

Веб-приложение для просмотра и управления расписанием. Проект состоит из
фронтенда на React, API на ASP.NET Core и базы данных SQL Server.

## Запуск всего проекта через Docker

### Что понадобится

- Docker Desktop с запущенным Docker Engine и поддержкой Linux-контейнеров.
- PowerShell.

### Первый запуск

Откройте PowerShell в корне репозитория — в папке, где находится
`docker-compose.yml`. Создайте локальный файл с настройками и запустите
сервисы:

```powershell
Copy-Item .env.example .env
docker compose up --build
```

Команда соберёт образы фронтенда и API, скачает образ SQL Server и запустит
все три сервиса. При первом запуске это может занять несколько минут.
Оставьте окно PowerShell открытым, пока работает приложение.

После запуска откройте:

- Приложение: <http://localhost:3000>
- API: <http://localhost:5101>
- Swagger для проверки API: <http://localhost:5101/swagger>

API применяет миграции базы данных при запуске. Данные SQL Server хранятся
в Docker-томе `sql_data` и сохраняются после остановки контейнеров.

### Остановка и повторный запуск

Чтобы остановить приложение, нажмите `Ctrl+C` в окне с логами, затем из
корня репозитория выполните:

```powershell
docker compose down
```

Эта команда удалит контейнеры, но сохранит данные базы. Чтобы снова запустить
проект:

```powershell
docker compose up
```

Если менялся код API или конфигурация образов, пересоберите образы:

```powershell
docker compose up --build
```

Исходный код фронтенда подключён к контейнеру: изменения обычно отображаются
после автоматической перезагрузки страницы.

### Настройки и безопасность

Файл `.env.example` содержит пароль SQL Server только для локальной разработки.
При необходимости измените пароль в `.env` перед запуском. Не используйте
примерный пароль вне локальной доверенной среды и не публикуйте `.env`.

## Команды фронтенда без Docker

Эти команды запускают только React-фронтенд. Для работы всего приложения
отдельно также нужны запущенные API и SQL Server.

Перейдите в папку `frontend` и установите зависимости:

```powershell
npm ci
```

Доступные команды:

### `npm start`

Запускает фронтенд в режиме разработки по адресу
<http://localhost:3000>. Страница перезагружается при изменении исходников.

### `npm test`

Запускает тесты в интерактивном режиме. Для однократного запуска в CI:

```powershell
npm test -- --watchAll=false
```

### `npm run build`

Создаёт оптимизированную production-сборку в папке `build`.

### `npm run eject`

Извлекает настройки Create React App в проект. Операция необратима; обычно
для работы над приложением она не требуется.

## Ученики и школьные курсы

После входа с JWT доступны страницы:

- преподаватель: `/teacher/students`, `/teacher/students/:id`;
- администратор школы: `/admin/school/students`, `/admin/school/courses`.

API учеников находится в `/api/students`, каталог курсов — в `/api/courses`.
Школьные изменения требуют членства в школьном workspace; преподаватель
получает только назначенных ему учеников. В standalone workspace доступны
только личные ученики преподавателя. Назначать школьных учеников может
администратор школы. Заметки преподавателя доступны автору, администратору
его школы — для чтения.

Миграция `AddStudentManagement` запускается API автоматически при старте
на SQL Server. Для ручной публикации можно сформировать идемпотентный SQL
скрипт из каталога `backend`:

```powershell
dotnet ef migrations script --idempotent
```

Формы учеников поддерживают контакты родителей/опекунов и назначение
школьных курсов. Активное пространство определяется JWT; переключателя
workspace для пользователей с несколькими членствами пока нет.

## Календарь занятий

Преподаватель открывает `/teacher/calendar`; администратор школы —
`/admin/school/calendar`. Календарь поддерживает день, неделю (понедельник–
пятница) и месяц, фильтры по ученику и курсу, создание разовых занятий и
еженедельных серий, редактирование одного занятия или будущих экземпляров
серии, статусы и перенос с журналом причины. Серии и экземпляры хранятся в
БД; для активной серии ближайшие занятия дополнительно материализуются при
запросе календаря.

API: `/api/lessons` и `/api/lessons/series`. Занятия доступны только
преподавателю назначенного ему ученика в текущем пространстве либо
администратору текущей школы. Время занятия хранится в UTC, а серия задаётся
локальными днём недели и временем в обязательной IANA/системной зоне,
например `Europe/Kyiv`. Несуществующее время при переводе часов вперёд
сдвигается к первому допустимому времени; неоднозначное время при переводе
назад трактуется с более ранним UTC-моментом. Фронтенд использует часовой пояс
браузера; сервер не выводит зону из системных настроек.

Начальная генерация серии ограничена годом, последующие периоды материализуются
по запросу календаря; заданный срок серии ограничен десятью годами. Отдельные
старые слоты из legacy-модели `Lesson` автоматически не переносятся: в них нет
календарной даты или часового пояса, поэтому безопасное преобразование
невозможно без уточнения пользователем. Автоматический импорт legacy-слотов
отложен.

## Финансы ученика

В карточке ученика отображаются журнал тарифов, оплаты, корректировки и два
отдельных баланса. Финансовый API расположен в
`/api/students/{studentId}/finance`; преподаватель видит финансы только
назначенного ему ученика в текущем пространстве, администратор школы — ученика
своей школы. Оплата хранится в UAH с датой, суммой и числом оплаченных занятий.
Денежный баланс рассчитывается как начисления минус оплаты: положительное
значение — долг, отрицательное — предоплата. Остаток занятий считается отдельно.

Тарифы имеют неизменяемую историю с датой начала действия. Исправление оплаты
создаёт отдельную аудируемую корректировку с обязательной причиной; повтор
запроса с тем же ключом идемпотентности не создаёт дубликат.
При переходе занятия в `Completed` или поздней отмене вызывается
`StudentFinanceService.RecordLessonChargeAsync`: начисление создаётся один раз
по ID занятия и использует тариф, действовавший на начало. Отмена ровно за
5 часов или раньше бесплатна; перенос не меняет начисления и не создаёт
финансовую запись. История переноса хранится отдельно от статуса нового
занятия.

Миграции `AddStudentFinance` и `AddLessonSystem` применяются API при старте
вместе с остальными миграциями. Проверка и публикация SQL Server-скрипта:
`Set-Location backend; dotnet ef migrations script --idempotent`.
## Домашние задания

После входа откройте «Домашние задания». Преподаватель может назначить работу
ученику или на его школьный курс, отфильтровать задания по ученику/курсу и
поставить оценку от 0 до 100. Ученик видит только назначенные ему задания и
может отправить текст, HTTP(S)-ссылки и изображения JPEG/PNG. Новую попытку
можно отправить после оценки предыдущей.

API находится в `/api/homework`. Вложения доступны только через
авторизованный маршрут `/api/homework/attachments/{id}`; прямые публичные URL
к файлам не создаются. По умолчанию принимается до пяти файлов по 5 MiB каждый.
Файлы хранятся вне web-root в `backend/App_Data/homework`; Docker использует
отдельный том `homework_files`. Путь можно изменить настройкой
`HomeworkFiles:StoragePath`. Миграция `AddHomeworkManagement` применяется API
при старте вместе с остальными миграциями.
